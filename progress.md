# Current project progress — 2026-09-20

The simulator environment, road network, Veins connection, emergency-message relays, traffic beacons, static and dynamic A*, mist/fog/cloud services, forced fog fallback, traffic-light preemption, logging, and result processing are implemented. The stock Veins example passed using OMNeT++ 6.3.0, Veins 5.3.1, and exact SUMO 1.18.0. The four main configurations completed a medium-traffic, seed-1 run; all four recorded accident arrival at t=205 s and an EV response time of 138 s. A separate forced mist failure produced and applied a fog route.

The 19 main validation checks are documented in [docs/VERIFICATION.md](docs/VERIFICATION.md). Direct EM delivery, vehicle and RSU multihop delivery, duplicate suppression, and TTL expiration passed. Static routing and a congestion-driven route change passed. The traffic-light log records actual yellow, all-red, green, and restoration states. The congestion stress case changed route but did not arrive by its 300-second cutoff; no dynamic response-time benefit is claimed from it. Single-seed graphs cannot provide meaningful standard deviations or 95% confidence intervals.

The full matched experiment (4 configurations × 3 densities × 30 seeds) has started through `scripts/run_full_batch.sh`. At this checkpoint, 4 of 360 batch scalar files are complete, covering all four low-traffic seed-1 cases; the runner is continuing with seed 2. It skips already completed runs and writes raw outputs to `results/raw/`. After completion, run `python analysis/process_results.py --batch --require-all` for the full comparison.
